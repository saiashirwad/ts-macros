# Inference gaps and fixes

- Gap: `inferExpressionType` only handles the early IR set; newer nodes like `new`, `this`, `optional-member`/`optional-call`, `as`, `satisfies`, `non-null`, `arrow`, `update`, `tagged-template`, and `assignment` all fall through to `unknown`, so the emitted `tsType` for those constructs is wrong or missing. Solution: add explicit cases that return the annotated type (e.g., `as`), unwrap constructors/`ClassRef` instance types for `new`, propagate underlying member/call types and append `| undefined` for optional chaining, mirror arrow return annotations or inferred body types, return number for updates, left-hand type for assignments, and tag return type or string fallback for tagged templates.
- Gap: The `binary` handler returns `number` for `"+"` before checking for string concatenation and also forces `&&`/`||` to `boolean`, so both string concat and short-circuit value typing are wrong. Solution: special-case `"+"` first (string if either side is string literal/descriptor, else number/unknown) and model `&&`/`||` as unions of operand types (optionally narrowing falsy/truthy later) instead of boolean.
- Gap: Nullish coalescing (`nullish`) currently unions left and right without removing `null | undefined`, disagreeing with the DSL’s `NonNullable` typing. Solution: strip `null`/`undefined` from the left descriptor before unioning with the right to align emitted annotations with the DSL contract.
- Gap: The inference context is unused in practice—`$.let`/`$.const` call `inferExpressionType` with the default empty context—so any expression that references earlier bindings infers `unknown`. Solution: thread an `InferenceContext` through block builders (or at least seed it with each `VarRef`’s `tsType`) so variable lookups can retrieve previously inferred/annotated types.
- Gap: `normalizeToExpression` emits `{ type: "literal", value: null }`, but `LiteralExpression.value` and `types.literal` exclude `null`, forcing casts and making inference unsound for null literals. Solution: widen the literal value union (and type descriptor) to include `null` or introduce a dedicated null literal node that inference and Babel translation understand.
- Gap: Function type inference loses parameter shapes. `InferTSType` uses `InferParamTupleInternal` (lines 18–27 in `src/types.ts`), which returns `unknown` for every position and ignores rest/optional markers, while a correct `InferParamTuple` exists lower in the file but is unused. Solution: swap `InferTSType`’s function branch to `(...args: InferParamTuple<NormalizeParams<P>>) => ...` and remove the dead/incorrect internal helper.
- Gap: `UnionToIntersection` is a stub aliasing the input, so intersection descriptors aren’t reflected in inferred TS types. Solution: implement the standard conditional trick (`U extends unknown ? (k: U) => void : never` …) so intersections collapse correctly.
- Gap: Planned phantom-typed `ClassRef`/`EnumRef` helpers and shape inference are absent from `src/refs.ts`/`src/types.ts`, meaning `$.new`/enum builders can’t convey instance or member value types beyond `unknown`. Solution: add `ClassRef`/`EnumRef` wrappers plus accompanying `InferClassShape`/`InferEnumValue` helpers and teach `inferExpressionType` to unwrap them when used as constructors or values.
- Gap: `types.function` and `TSTypeDescriptor`’s function variant lack optional/rest metadata, so even with better inference the signature loses parameter optionality and rest element typing. Solution: extend the function descriptor to carry `{ type, optional?, rest? }` entries (mirroring `FunctionParam`) and update builders/inference to preserve those flags.
